# Usage metrics Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans; implementation inline in this session.

**Goal:** Medir atividade diária e funções utilizadas, sem transmitir dados clínicos.
**Architecture:** Módulos independentes de métricas no navegador, Worker Cloudflare separado, D1 e painel com token privado.
**Tech Stack:** JavaScript ESM, node:test, linkedom, SQLite/D1.
**Spec:** docs/superpowers/specs/2026-11-01-usage-design.md

## Global Constraints
- Preservar cálculos, relatórios e integração Fenton existentes.
- Esquema fechado; nenhuma leitura/transmissão de campos clínicos.
- Dia America/Manaus; fila 200/7 dias; retenção servidor 90 dias.
- Endpoint não configurado = não coletar.

## Review Focus
- Retries e falhas após gravação: deduplicar evento sem duplicar aberturas.
- Offline e virada do dia: manter data original e renovar visitante.
- DNT/GPC/opt-out: nenhuma requisição, fila apagada.
- Payload com identificação clínica: rejeitar antes de persistir.
- Token ausente ou incorreto: nenhuma estatística exposta.

## Resultado e revisão

Revisão independente encontrou e reproduziu conflito de preferência/fila entre abas. Corrigido com preferência relida a cada operação, eventos em chaves independentes e Web Locks para criação do identificador diário onde disponível. Revisor confirmou 10/10 testes do cliente, sem bloqueadores críticos/importantes. Limitação residual de corrida de identidade em browsers sem Web Locks documentada. Worker/D1 e painel testados localmente, sem certificação de produção.

A etapa de implantação segue pendente; PR deve ser rascunho e endpoint fica vazio. Os itens marcados de entrega representam a preparação e verificação local, não ativação em produção.
